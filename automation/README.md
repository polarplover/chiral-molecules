# Issue 入口过滤

`issue_intake.py` 是服务器控制器使用的无模型过滤规则，只处理路由，不执行帖子或仓库中的代码。

- 游戏生成的 `socrates-question` 成绩/评论记录，没有故障或改进诉求，且记录外只有游戏生成的说明：静默跳过。
- 标题明确为成绩/体验/评论、正文是可识别的简短成绩或感想：静默跳过。
- 包含故障描述、bug、建议、改进请求，或无法明确识别的自由文本、损坏/多份记录：保留后续审查，避免仅凭标题误丢问题。
- 跳过发生在源码下载和模型调用之前，不回复、不创建 PR、不关闭或修改来源 Issue，不影响社区榜单工作流。
- 本地仅记录 `ignored-community` 和标题/正文指纹。内容修改后重新判断；不会清空既有配额、已发布 PR 或运行中的任务。

无模型规则无法穷尽自然语言。存在歧义时保留审查；不要把关键词过滤当作安全边界。

测试：`python3 -m unittest discover -s automation -p 'test_*.py'`。该测试已加入现有 hosted CI。

部署时，管理员将本文件夹的 `issue_intake.py` 安装到 `/opt/issue-autofix/issue_intake.py`（root:root，0644）。可信控制器的 `scan()` 在已有 PR/运行中任务保护之后、模型初审之前调用 `community_only(issue)`，返回 true 时保存跳过状态并直接处理下一个 Issue。服务器不会从 main 自动加载或执行该文件，规则更新须经管理员验证后部署。
